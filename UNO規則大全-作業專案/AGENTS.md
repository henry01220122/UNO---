# UNO 規則大全：AI 開發規範

## 專案目的
建立可直接以瀏覽器閱讀的繁體中文 UNO 規則網站，延續 UNO 智慧裁判的規則查詢與計分主題。以清楚分類與版本區分，協助玩家解決規則爭議。不是完整牌局模擬器，也不是即時 AI 聊天服務。

## 檔案結構與執行
- `index.html`：網站唯一必要檔案，包含語意化 HTML 與內嵌 CSS。
- `README.md`：網站用途、啟用方式、來源與擴充說明。
- `AGENTS.md`：本開發規範。
直接以瀏覽器開啟 index.html 即可。不得為基本閱讀功能增加 Python、Node.js、API 金鑰或付費服務依賴。
GitHub Pages 發布時以 main 分支根目錄為來源；不可把本機 127.0.0.1 網址當成公開成果。

## 固定頁面分類
目前依序為基本玩法（basics）、功能牌（cards）、特殊情境（situations）、計分方式（scoring）、自訂玩法（house）、資料來源（sources）。
保留現有錨點，避免導覽連結失效。新增分類時，同步新增導覽與唯一 section id。

## 內容格式
一般規則使用 article.rule，依序包含短標籤、h3 標題、規則說明；有例子時用 p.example。
功能牌使用相同 rule 結構，加上有文字或 aria-label 的示意卡牌。
特殊情境使用 details.faq、summary 問題及 div.answer 答案，供鍵盤與觸控操作。
自訂玩法必須有 badge house 標記，不可與經典規則混寫。
每項新規則須確認版本、觸發條件、結果、例外、來源；資訊不足時不要自行補成官方規則。

## 來源與準確性
以 Mattel 對應產品說明書作為官方規則來源；新增來源放在 sources 區並標示用途。
使用自己的繁體中文摘要，不整篇翻印官方說明書。
經典 +2 不疊加轉嫁；+4 需確認手上沒有目前顏色的牌；不可簡化為「只要有任何可出的牌就不能出 +4」。
兩人局、No Mercy、Flip、手機版及玩家自訂玩法分別處理，不能混用。
數字牌為牌面分數，跳過／反轉／+2 為 20 分，萬用／+4 為 50 分。
維持非官方學習網站與商標歸屬說明。不使用未授權的官方圖像素材。

## 視覺規格
使用暖白背景、深色文字，UNO 紅黃藍綠作為重點配色。沿用 :root 色彩變數。
頁面最大寬度 1180px；桌面卡片多欄，手機單欄。維持 580px 與 850px 響應式設定。
沿用 section-head、number、grid、rule、faq 等元件類別，不為每條規則重寫一套樣式。
內文字級至少 14px；標題階層依 h1 → h2 → h3，整頁只有一個 h1。
不只靠顏色傳達牌型。保留鍵盤焦點、跳至內容連結與 reduced-motion 支援。

## 新增內容的流程
1. 查證來源與適用版本。
2. 選擇既有分類及對應 HTML 元件。
3. 撰寫短說明，必要時加入一個具體情境例子。
4. 補上來源，檢查和其他規則是否矛盾。
5. 更新 README 的內容概述及修改紀錄。
6. 驗證桌面、手機、導覽、鍵盤與來源連結。

## 新增頁面的流程
目前優先維持單檔。若明確要求獨立頁，檔名採小寫英文與連字號，例如 two-player.html。
沿用既有配色、導覽、標題層級、規則元件與來源區。加入首頁入口及返回首頁連結，路徑使用相對路徑。
不要把 No Mercy 內容直接覆蓋經典規則。新版本另頁並在標題標示版本。

## 驗收
- index.html 可獨立開啟，不依賴外部字型或程式庫。
- 所有頁內連結都有對應且唯一的 id。
- 手機寬度下沒有橫向溢出，標題、卡牌與表格沒有遮擋。
- details 可用滑鼠與鍵盤展開及收起。
- 官方與自訂玩法標示清楚；77 分範例計算正確。
- 修改只作用於本專案，不改動其他同步參考檔案。
- 回報實際完成與驗證結果，不把未部署寫成已公開，也不保證評分。

## 延伸提示範例
「依 AGENTS.md，在特殊情境新增一則『最後一張是 +2 時如何計分』，沿用 details 元件，補上情境例子與官方來源，並確認手機排版。」
AI 可依固定分類、格式、來源與驗收規則延伸，不需要重新猜測整個網站的設計。
